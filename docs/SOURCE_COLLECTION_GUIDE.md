# 정보원 수집 가이드 (Phase 4-2)

기준일 2026-10-27. 아래 결과는 이 개발 PC에서 **실제 외부 사이트에 접속해** 얻은 값이다(HTTP 모의 아님). 외부 사이트에 신규 문서가 없으면 신규 0건이 정상이며 건수를 만들어 내지 않는다.

## 1. 정보원 점검표 (실제 접속·수집 결과)
| 정보원 | 방식 | 접속 상태 | 실제 결과(2026-10-27) | 비고 |
|---|---|---|---|---|
| Federal Register — FCC(방송·전파) | REST API | **정상 수집** | 20건 조회, 신규 5·중복 15 | 공식 API, 키 불필요 |
| Federal Register — NHTSA × 자율주행차 | REST API | 정상 수집 | 20건, 신규 1·중복 19 | |
| Federal Register — BIS / NIST / NTIA / OSTP / Copyright Office (5곳) | REST API | 정상 수집 | 각 20건, 신규 0·중복 20 | 새 고시가 없어 0건(정상) |
| NIST News | RSS | 정상 수집 | 40건, 신규 0·중복 40 | robots.txt 허용 확인 |
| W3C News | RSS(Atom) | 정상 수집 | 25건, 신규 0·중복 25 | robots.txt 허용 확인 |
| **arXiv API — cs.AI 최신 논문(신규)** | REST API(Atom) | 정상 수집 | 30건, 신규 30(제목·초록 분류 30건) | 공식 API, 호출 간격 3초 |
| arXiv cs.AI RSS(기존) | RSS | **접속 제한** | robots.txt 불허로 수집 거부 | 우회하지 않고 비활성화, 공식 API 정보원으로 대체(과거 자료 보존) |

관찰: 이전 수집기는 robots.txt를 확인하지 않아 arXiv RSS를 수집하고 있었다. 새 수집기는 RSS·HTML·PDF 수집 전에 robots.txt를 확인하고, 거부되면 `접속 제한`으로 표시한다. 공식 API(Federal Register·arXiv API)는 API 이용 안내를 따르며 robots.txt 검사 대상이 아니다.

## 2. 수집 방식
| 방식 | 설명 | 구현 |
|---|---|---|
| REST API | 공급자별 파서(`federal_register`, `arxiv_api`) | 공식 응답에서 제목·기관·발표일·원문 URL·문서번호를 읽는다 |
| RSS·Atom | 공식 피드 | feedparser, 발표일·수정일 분리 |
| 공개 HTML | 목록 페이지의 링크(같은 사이트 또는 설정한 패턴) | BeautifulSoup — 스크립트는 실행하지 않는다 |
| 공식 PDF | PDF 1건 — 제목·URL·파일 내용 해시 | `%PDF` 형식 검사, 변경 감지 |
| 메타데이터 전용 | 제목·링크·발표일만 저장(본문 미저장) | 이용조건상 전문 저장이 불가한 정보원용 |

## 3. 수집 흐름(작업 ID로 추적)
정보원 설정 조회 → 안전 규칙 검사 → 공식 URL 연결·HTTP 응답 확인 → 신규 자료 식별(제목·기관·국가·발표일·수정일·원문 링크·언어) → 중복·수정 판별 → DB 저장 → ICT 9대 분야 자동 분류(규칙 기반, 신규 8건은 전문 추출까지) → 이슈 연결·후보 추천 → 화면 갱신.
- **'지금 수집'**: 작업(`collection_jobs`)을 만들고 서버가 처리한다. 작업 상태: 대기·수집 중·완료·실패·취소·시간 초과·중단. 화면을 닫아도 작업은 계속된다. 같은 정보원 연속 클릭은 기존 작업을 돌려준다(DB 유니크 제약).
- 서버가 도중에 멈추면 heartbeat 가 끊긴 `running` 작업을 `중단됨`으로 정리해 다시 수집할 수 있다.

## 4. 중복·원문 변경
- 식별자: 정보원 ID · 공식 문서번호(예: FR `2026-21821`, `arxiv:2610.35868`) · 정규화 URL(소문자 호스트·https·조각/추적 파라미터 제거) · 내용 해시 · 발표일/수정일/수집일(별도 필드).
- 같은 문서·같은 내용 → 중복(새 행 없음). 다른 정보원이 같은 URL을 이미 가지고 있어도 중복 처리.
- 같은 문서·내용 변경 → **새 버전 행**(`version_no`, `previous_version_id`)으로 저장하고 이전 버전은 보존, 목록에는 최신본만 표시(`v2` 배지). 그 문서가 속한 이슈는 '재검토 필요'로 표시하고 감사 로그(`document.version`)를 남긴다.

## 5. 정보원 관리 화면(관리자·정보원 관리자)
`출처·수집 관리`: 목록(방식·주기·접속 상태·최근 성공·최근 신규), 정보원 등록·편집(주소·방식·분야·국가·주기·요청 간격·robots 준수), **연결 테스트**(저장 없이 실제 접속해 항목을 읽어 사유 표시), 지금 수집(진행 상태·취소), 비활성화(삭제 없음, 설정 변경 이력 보존), 수집 이력.
접속 상태 라벨: 정상 수집 · 메타데이터만 수집 · 접속 제한(403/429/robots) · 주소 변경(404/410) · 일시 오류 · 미검증.

## 6. 자동 수집(예약)
- 정보원별 수집 주기(`interval_minutes`)와 작업 기록은 DB에 있어 재시작해도 유지된다.
- 작업자: `python -m app.worker`(계속 실행) 또는 `--once`(작업 스케줄러·cron). 실패한 정보원은 15분부터 점차 늘려 재시도(최대 설정 주기).
- Windows: `scripts\start-worker.ps1` 또는 작업 스케줄러에서 `apps\api\.venv\Scripts\python -m app.worker --once` 를 15~60분마다 실행. 서버(Docker): `worker` 서비스.
- GitHub Actions 예약 실행은 지연·누락·비활동 중단 가능성이 있어 사용하지 않는다(유일한 경로로 의존 금지).
- 검증: E2E 4-2 F — 작업자만 실행해 `trigger=schedule` 작업이 실제 수집을 하고, 주기 전에는 다시 실행되지 않음.

## 7. 수집 보안·이용조건
http/https 만 허용·포트 제한·계정정보 주소 금지, DNS 확인 후 내부망·루프백·예약 주소 차단(리디렉션마다 재검사), 응답 8MB 제한, 연결 6초·읽기 15초 시간 제한, 호스트별 최소 요청 간격(기본 3초), robots.txt 준수, HTML 스크립트 미실행, 모든 정보원 변경·수집 요청은 감사 로그. **한계**: DNS 확인과 실제 연결 사이의 DNS 재바인딩은 완전히 막지 못하고(관리자 전용 기능으로 위험 완화), XML 엔티티 폭탄·압축 폭탄에 대한 별도 검사는 응답 크기 제한으로만 방어한다. 로그인·CAPTCHA·접근 제한은 우회하지 않는다.
저작권: 본문은 요약·초록 범위와 확보 가능한 공개 원문만 저장하고 항상 원문 링크를 함께 보존한다. 이용조건상 전문 저장이 허용되지 않는 정보원은 `메타데이터 전용`으로 등록한다.
