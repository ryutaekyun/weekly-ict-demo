# 시연 가이드 — 공개 읽기 전용 화면 + 로컬 통합 사이트

이 플랫폼은 **유료 AI(LLM)를 사용하지 않는 무료 시연 버전**이다. 분류·이슈 묶음·후보 추천은 키워드·규칙 기반 자동 분석이며 연구원이 검토한다(생성형 AI가 분석·검증한 결과가 아니다). 유료 외부 AI 호출은 코드 수준에서 차단되어 있어 키·환경변수·관리자 설정으로 켤 수 없다.

## 1. 두 가지 시연 환경

| 구분 | 주소 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|---|
| **공개 시연(읽기 전용)** | https://ryutaekyun.github.io/weekly-ict-demo/preview/ (기존 시연: 같은 주소의 루트) | 대시보드·수집 현황, 9대 분야 자료 탐색·검색·정렬, 공식 원문 새 탭 열기, 핵심 이슈·후보주제(추천 점수·산정 근거·논쟁 가능성), 시범 보고서·카드뉴스 다운로드 | 로그인·저장·후보 수정·원고 작성·파일 생성(정적 스냅샷이라 서버가 없음) |
| **로컬 통합 사이트** | http://localhost:3000 | 위 전부 + 후보 수정·검토의견·근거 추가/제외, 원문 작업대로 직접 집필, 작성 점검, 보고서·요약본 DOCX/PDF, 카드뉴스 PPTX/PNG | — |

공개 화면의 데이터는 **수집 시점의 정적 스냅샷**이다(화면 상단에 기준일 표시). 개인정보·검토의견·비공개 원고·키·모의 AI 결과는 스냅샷에 포함되지 않는다.

## 2. 로컬 실행 (명령어를 외울 필요 없음)

1. 저장소의 `scripts\start-demo.bat`을 더블클릭한다(또는 PowerShell에서 `.\scripts\start-demo.ps1`).
2. 화면에 `[정상] FastAPI`, `[정상] Next.js`, `[정상] DB`가 나오면 브라우저에서 http://localhost:3000 을 연다.
3. 점검만 하려면 `scripts\check-demo.bat`, 끝낼 때는 `scripts\stop-demo.bat`.
4. 오류가 나면 각 줄에 **원인과 해결 방법**이 함께 표시된다(Node.js/가상환경/패키지 미설치, 포트 사용 중, DB 마이그레이션 등).

## 3. 시연 계정(가상 계정만 사용, 비밀번호는 저장소에 없음)

- 개발 DB를 처음 만들 때: `apps\api`에서 `.venv\Scripts\python -m app.seed` — 가상 연구원·승인권자 계정이 만들어지고 **비밀번호는 그 실행에서 한 번만 출력**된다.
- 시연 전용 계정을 따로 만들려면: `apps\api`에서 `.venv\Scripts\python -m app.seed_demo_accounts` — `demo-researcher@example.com`, `demo-approver@example.com`, `demo-admin@example.com`을 만들고 **무작위 비밀번호를 `apps\api\demo_accounts.local.txt`에만 저장**한다(`.gitignore` 대상, 공개 저장소에 올라가지 않음). 같은 이메일이 이미 있으면 건드리지 않는다.
- 자동 테스트용 고정 계정(`e2e-*@example.com`)은 시연에 쓰지 않는다.

## 3-1. 로컬 사이트 안의 '시연 가이드' 화면

로그인 후 왼쪽 메뉴 **시연 가이드**에서 아래 3가지 경로를 단계별로 따라갈 수 있다(링크는 실제 화면으로 이동할 뿐 기능을 대신 실행하지 않는다).

## 4. 대표 시연 시나리오 3종 (실제 DB의 공개 자료 기준)

### 시나리오 A — 통신·방송·전파 정책동향 (FCC 공식 자료)
1. 대시보드에서 **방송·전파·위성** 분야 건수를 누른다 → 해당 분야로 분류된 자료 목록(건수는 실제 조회 결과).
2. `Upper C-Band (3.98–4.2 GHz); Expanding Flexible Use of the 3.7 to 4.2 GHz Band`(FCC, 2026-10-19 게시) 제목을 누르면 **공식 원문(federalregister.gov)이 새 탭**으로 열린다.
3. **상세 분석** → 규칙 기반 분류·활용가치·핵심 내용 → **관련 이슈** → 후보주제.
4. 후보주제 화면: 추천 점수와 **산정 근거**(정책·산업 영향/시의성/국내 관련성/신규성/분석 가능 깊이), 논쟁 가능성(근거가 없으면 '논쟁 없음'), 발표 시점·후속 동향. 제목·분야·검토의견·상태(선정·보류·**추가 조사 필요**)를 수정하고 저장 → 새로고침 후에도 유지된다.
> 참고: DB에서 이 문서의 분야는 방송·전파·위성(bcast)으로 분류되어 있어 '통신·네트워크'가 아니라 그 분야에서 찾는다.

### 시나리오 B — 기술·정책 쟁점 탐색 (검색 → 비교 → 후보 등록)
1. **인공지능·데이터** 분야에서 키워드 검색·기간·정렬 필터를 적용하고, 상세 화면에서 뒤로 가도 조건이 유지되는지 확인한다.
2. 복수 문서가 묶인 **핵심 이슈**를 열어 관련 원문·타임라인·후속 변화를 비교한다. 상반된 주장이 규칙으로 확인되지 않으면 논쟁으로 표시하지 않는다.
3. 후보주제에서 **근거 원문 추가·제외**, 새 후보 등록, 검토 의견을 남긴다.

### 시나리오 C — 보고서·요약본·카드뉴스 제작 (연구원 검토 시범 원고)
1. **연구·집필 작업실**에서 시범 작성 원고를 연다. 왼쪽 **원문·근거 작업대**: 원문 열람(새 탭), **인용 넣기**(기관·「제목」·발표일 + 미검증 각주), **발췌문 고르기**(원문 문단을 직접 선택해 삽입). 위쪽 **후보 제목 불러오기**, **목차 템플릿 삽입**(커서 문단 뒤에 덧붙이며 기존 문장은 덮어쓰지 않음).
2. 오른쪽 **작성 점검**: 근거 발췌문과 문장의 날짜·수치 일치, 시행일·준수 시한 등 날짜 역할 혼동, 단위·부등호·부정 반전 가능성, 중복 문장·중복 출처, 근거 미검증 문장을 알려 준다. **원문을 가져왔다고 사실이 검증된 것으로 처리하지 않는다.**
3. **보고서·요약본 제작**: 일반호 구성 → 요약본(원고 변경·시행일 변경 시 재검토 표시) → DOCX·PDF 다운로드(버전·생성일 기록).
4. **카드뉴스 제작**: 보고서 문장으로 카드 생성 → PPTX·PNG 다운로드. 모든 시범 출력물에는 **시범·내부용·IITP 미확인** 표시가 붙는다.

## 5. 알려 둘 점
- 이 시연에는 생성형 AI가 쓴 문장이 없다. 규칙 기반 자동 분석 결과는 연구원 검토 전 초안이다.
- Word·PowerPoint 실제 열람 호환은 검증하지 못했다(LibreOffice 변환으로만 확인).
- 새 정보원은 사용자가 직접 제공하기 전까지 추가하지 않는다. 분야별 자료가 적어도 분류 기준을 느슨하게 바꾸지 않으며, 자료가 없는 분야(예: ICT 융합기술)는 빈 상태로 둔다.
